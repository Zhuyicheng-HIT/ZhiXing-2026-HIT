# 分层进场与空间预约

2026-10-06 当前默认配置由 `config/coordination.json` 固定为：前排（起飞位东侧）uav6=65m、uav4=55m、uav2=40.5m，后排（西侧）uav5=60m、uav3=50m、uav1=45m。按上述顺序每2s放行；返场沿用本机进场高度。各进场航线避让与本机高度相差小于8m的其他起飞位的水平12.5m缓冲区，仍以名义连续轨迹校验和原生12m路径预约作为约束，不保证实机无碰撞。下文110/100/90/80/70/60m顺序和返场独占均为历史版本。

本页描述空间预约策略与142站历史复验；当前112站覆盖方案见 `sparse_coverage.md`，预约返场与最新双科目结果以 `reserved_returns.md` 为准。本页“返场独占”仅描述历史版本。进场预约算法与相交路径有界试验仍适用，但不能用本页旧完整任务耗时代替当前耗时。

## 执行顺序

六机仍统一解锁并在同一个调度周期发送起飞命令，实际到 2m 后等待悬停确认。入场层按首站距离由近到远分配 110/100/90/80/70/60m，并按高到低放行。

默认 `config/coordination.json` 的 `entry_policy` 为 `layered_reserved`。上层机实际爬升到本机高度且稳定后，必须先取得本机首段 INGRESS 的空间预约，才能允许下一架申请爬升；不再等待上层机到远处作业区并完成下降。这样可以在不同高度并行入场，但不允许下层机抢先占用上层机尚未预约的首段路径。

预约检查覆盖全部任务航段，而不只是进场。新航段从实际 ENU 位置到目标点形成三维线段；其他飞机从其最新位置到已获准目标点形成剩余预约线段，无预约的飞机视为当前悬停点。与任意其他线段的最近距离必须至少为配置的 12m。只检验端点间距是不够的：两条端点很远的路径可能相交，下降竖线也可能穿过另一架的水平路径。

已授权航段采用非抢占执行，不因另一架的新申请中途改道。冲突申请方锁存当前位置等待，游标、观察点不变，显示 `WAIT_PATH_RESERVATION`；路径解除后自动重新申请，不把等待当作任务失败，不独立 RTL。暂停或协调故障清除旧授权、保持实际位置，恢复后重新核对剩余路径，已放行身份和任务断点保留。

跨片高层转场必须等全部飞机完成入场，再沿用共享独占令牌。返场仍为完成任务后登记 FIFO，等待独占通道，令牌直到实际落地并解除锁定才释放；本次没有放开并行返场。

## 安全边界

12m 是未实机标定的命令路径间距，原来的实际采样 10m 全队协调保持仍保留。预约检查假设飞机沿已授权直线航段执行，不证明存在风扰、惯性、滞后、控制器异常时的连续物理无碰撞。不能将“授权线段分离”和“实际轨迹处处分离”混为一谈。真实飞行前仍需要测量跟踪误差、停距、姿态及通信时延，并确定保护包络；当前 `hardware_authorized=false`。

当前扫描矩形、视角和目标事件仍为合成；跨树林仍必须显式选择条件仿真许可，严格禁穿模式的几何不连通问题没有被预约调度解决。运动学预演沿用名义时间轴，并不复刻原生反馈执行器的每一次预约等待，不能据此判定比赛时限。
