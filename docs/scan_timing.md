# 扫描计时与证据配置

`config/scan_profile.json` 是规划与观察协议的共同配置来源。每个 SCAN 航段的名义时长等于“云台视线在地面的移动时间 + `minimum_observation_s`”；视线移动速度上限为2m/s，飞机在扫描站位悬停。计划记录完整 `observation_conditions` 和扫描运动模型，协议初始化会核对配置和所有扫描时长。修改配置后必须停止服务、重新生成计划并重启，不能在旧计划上热换观察窗口。

当前默认窗口仍为 **2 秒仿真假设**，至少 6 个不同源帧；每站九个矩形内观察点仍保持原顺序。附件 ROS 对接规格建议从稳定后3秒开始实测；这不是已经完成的相机标定。80m扫描范围、平地和2m/s视线移动都是估计参数，需要根据真实解码、推理速率、清晰度及目标检测结果替换，不能为赶比赛时限直接缩短。

外部观察证据时间使用 UNIX UTC 秒；原生合成扫描使用飞控仿真时间。20 倍仿真不会把真实图像证据的 3 秒压缩成墙钟 0.15 秒。六机可以独立等待结果，当前机只有获得有效完成证据才前进；配置同源不意味着真实扫描耗时必然等于名义窗口，还存在指向、稳定、解码和通信等待。

观察条件进入计划版本哈希；窗口或帧数变化后拒绝复用旧断点、旧结果。旧版不包含观察条件的计划也需要重新生成。执行超时必须大于观察窗口与最短稳定时间之和；帧数少于 6、布尔值当数值、非有限数值等配置拒绝加载。

```bash
python3 scripts/validate_scan_timing.py
python3 scripts/validate_scan_protocol.py
python3 scripts/validate_waypoint_executor.py
```

`validation/scan_timing_report.json` 只证明配置、版本和九点顺序一致性，不是六机物理或实机验收。航点位置不变，返航排队和最终等待时间会随扫描窗口重新计算；不能要求所有非扫描等待时长保持不变。

当前重新规划结果会记录在 `validation/work_only_scan_speed_report.json`：单站最大名义扫描时间约176.48秒，科目一和科目二搜索前段的名义总时长约5222.16秒，均不满足比赛时限。这是诚实的仿真估算，不是建议把飞机扫视速度提高到2m/s以上；后续必须用真实视场、目标密度和视觉组确认的扫描策略减少观察点或采用并行有效观察。

## 本版原生执行复验

`validation/sitl_scan_timing_report.json`：科目一默认 2 秒配置从零执行，六个 ArduCopter 4.7.1 实例完成全部 1278 次合成观察、故障恢复与降落解锁，实际飞控任务时间 **2572.0 秒（42.87 分钟）**，仍超过 25 分钟。采样最小三维间距 16.896 米、起降区外最低 40.464 米；采样工作区和比赛周界超出距离均为零。不是连续无碰撞证明，不包含真实相机、Gazebo 或投放。

`validation/concurrent_scan_timing_sitl_report.json`：六机实际到位后独立等待，五机并行接受合成帧证据；单机失败后原观察点以新尝试恢复、旧尝试被拒绝，其他飞机继续，协调故障保持全队且不独立 RTL。本测试是有界接口复验，不是第二次完整任务。

旧报告使用条件仿真跨树林权限，不能覆盖2026年10月6日确认后的当前空域策略。网页本轮通过脚本语法、页面/脚本/卫星底图 HTTP 交付检查；浏览器视觉及点击复验仍未完成。
