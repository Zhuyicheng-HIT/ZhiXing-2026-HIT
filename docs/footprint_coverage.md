# 用扫描覆盖规划站位，而不是沿边巡航

每个悬停站位对应一个模拟扫描矩形。规划目标是这些矩形的并集覆盖本机搜索区，不是让飞机轨迹遍历搜索区。树林不搜索，进出场仍须处于25点周界内。

算法先生成稀疏网格和贪心候选，再在不增加站位、保留每站独有覆盖面积的条件下向作业区内部移动站位。默认偏好距导航边界28m；这是软偏好，不是硬性禁飞距离。候选首先比较站位数量，再比较贴边惩罚及连接距离。细长地块和凹角可能仍需要近边站位；凹多边形中的连接路线也可能绕边，不能直接用越界直线替换。

配置位于 `config/coverage_planning.json`。工作空间、20m隔离带、进出场分层及2m/s扫描地速不变。扫描可以覆盖隔离带边缘，但飞机不能在作业时越出本机导航区域。

默认80m矩形对照：112个站位、100%名义覆盖保持不变。距比赛周界10m以内的站位由24个降为12个；触及该10m边缘带的NAVIGATE航段总长度由2207m降至1062m。这里统计的是满足条件的整段长度，不是边缘带内裁切后的长度，也不包含必要进出场航段。

网页勾选“扫描覆盖矩形”可看各站覆盖，显示仅裁切到所属搜索区。实线表示搜索站位间移动，虚线表示进出场和分层转场；关闭“完整路线”可单独检查覆盖，无需把每个覆盖边缘都飞一遍。

本版本没有声称最少站位或最短路线的全局最优。80m是未实测的平地矩形假设，不能证明房区遮挡下真实识别完整。九点逐点扫描仍约87.3分钟，明显超过25/30分钟，不能当作可参赛的完成时间。此修改解决贴边选点倾向，不解决视觉扫描协议过慢。

## 重启查看

WSL中停止旧服务，再执行：

```bash
cd /home/zyc/zhixin_2026_ws
python3 scripts/prepare_assets.py
python3 scripts/sim_server.py --port 8765
```

Windows浏览器打开 `http://localhost:8765` 并强制刷新。上述服务是运动学演示，不启动ArduPilot物理闭环；原有SITL启动方式见README，修改后也需要重新启动生成计划。

## 验证

```bash
python3 scripts/validate_footprint_coverage.py
python3 scripts/validate_work_only_scan_speed.py
python3 scripts/validate_simulation.py
```

报告 `validation/footprint_coverage_report.json` 分别记录原始候选和向内偏好后的名义几何结果。回归检查每架机自身未覆盖面积没有增加、站位及搜索连接合法性，不代替实机光学标定、地形建模或多机物理安全验证。

**已发现的分区限制：**房区uav_3的搜索多边形存在约307.83㎡细条残片，距本机可飞空间过远；80m扫描矩形不能单机覆盖这些残片。原版与新版都靠邻机扫描矩形补齐，因而全场100%不等于每机独立100%。网页覆盖矩形裁切到各自搜索区会保留这些空白，不应把它们误认为没有搜索需求。需要后续显式修订搜索归属；当前没有擅自扩大可飞区域或缩小隔离带。
