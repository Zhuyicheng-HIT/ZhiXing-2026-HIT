# 低密度站位候选规划

本页完整耗时记录是稀疏覆盖、独占返场的历史基线；当前预约返场与恢复到位门控的双科目复验见 `reserved_returns.md`，不能把32.38/32.35min作为当前耗时。覆盖算法及未标定限制仍适用。

本版以减少飞机悬停扫描站位为目标，而不是只画出更疏的航点。仍为六机，每区两架、既定直线20m隔离带、名义40m/指令40.5m工作高度；每站九点行优先顺序、2s假设观察窗口和至少六个不同源帧均不变。80m矩形是未标定的整个云台扫视范围，不是ZR10瞬时视场，也不是实机光学覆盖保证。

## 方法与适用范围

`config/coverage_planning.json` 默认 `sparse_grid_candidates`。规划器保留旧贪心方案作候选，再比较四种完整边长网格相位。网格点不得进入隔离带；边缘点投影到内缩导航区，剩余区域用原覆盖算法补齐，然后删除冗余矩形，按连通片和区域内路径排序。只选择在当前名义模型中覆盖不退化且站数更少的方案；站数相同时以路线长度估计择优。不保证全局最少航点或真实最短耗时。

网格接边可能没有重叠，尚无地形、遮挡、相机标定和位置误差覆盖裕度。不能把名义覆盖100%直接作为实际识别完整率。实机必须先实测保守有效扫视矩形；设置40/80/120m的逻辑测试只证明对应假设下的几何，不是批准扩大视场来通过比赛时限。

新计划共1008个观察点，原来1278个。全队矩形并集名义覆盖约100%，数值剩余约2.25e-11m²。房区uav_3自身搜索片仍有约307.83m²不能由它的安全站位矩形覆盖，依赖其他飞机视场跨过分区边界覆盖；不声称每架独立完成自己的片区。飞机本体不得跨作业分区，视场覆盖相邻片不等于允许越界。

比较证据为 `validation/sparse_coverage_comparison.json`，包含不变区域/隔离带/观察条件、逐站九点顺序、变更计划版本和拒绝旧断点。`validation/station_routes_report.json` 检查40/80/120m候选的连通片与覆盖，不能用其名义时间轴替代原生实际反馈耗时。

## 计时修正

六飞控准备阶段可能出现解锁、解除锁定、再解锁。旧计时保留了上次解除锁定终点，却把起点改成再次解锁时间，飞行中曾出现负时长。现保留首次解锁时间，再解锁清除旧终点；正在解锁飞行时始终用最新本机FCU时间，最终解除锁定后冻结该机时间，整队取最大值。没有通过截断负值掩盖问题，也不删除真实重试耗时。

`validation/fcu_timing_logic_report.json` 检查首次解锁、重复解锁、冻结终点和零时间戳。它是记账逻辑测试，不是六机时钟同步证明；FCU时间与外部相机UTC证据时间仍分别管理。首次稀疏双科目报告保留为 `sitl_sparse_coverage_initial_report.json` / `sitl_subject2_sparse_coverage_initial_report.json`，完成飞行但计时修正前证据不作为本版最终计时验收。

完成复验后默认服务回到5倍速、六机READY未解锁。`validation/ready_sparse_coverage_service_report.json` 单独检查新鲜飞控反馈、112站计划、网页脚本与卫星图HTTP交付，不代表浏览器视觉或点击通过。

树林跨越仍需明确条件仿真许可；严格禁止全高度穿树林时区域不连通没有解决。ZR10/YOLO仍合成，科二投放未完成，没有真实地形、连续物理无碰撞或硬件验收。网页脚本语法和HTTP检查与浏览器视觉/点击检查分开记录。
