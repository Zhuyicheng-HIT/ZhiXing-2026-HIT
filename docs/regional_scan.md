最大站位范围是站内云台可扫描的区域边长，不是一帧覆盖宽度。规划只扫本次分配的地块，各站的路径由地块形状定制。房区保持较密重叠，草区以较宽画幅粗扫。全机光轴地面速度仍为4m/s，飞机站间名义速度6m/s。高度、画幅和整站范围在`config/scan_profile.json`中设置。

平地正下视近似：`W = 2H tan(61.5°/2) / z`，`V = W / (16/9)`，因此`z = 2H tan(61.5°/2) / ((16/9)×V)`。60m无变倍画面约71.39×40.16m，选择38m纵向覆盖，对应约1.06倍相对焦距。SDK倍率刻度、畸变、斜视时梯形投影、机体航向导致的画面旋转及YOLO有效识别边缘尚未实测标定；地图显示的是轴对齐名义矩形，不能保证遮挡目标已被识别。

## 分区与进出场

出发搜索区新增原出发区东侧、树林西侧的余地：候选轮廓沿周界点1、25、24、树林西侧折线、13、9闭合，再与合法房区求交；不包含树林或起降框。两机按工作量重新选择直线分界，保留20m作业隔离。

六机同时起至2m、悬停3s，默认前排uav6/4/2、后排uav5/3/1，任务时刻5/7/9/11/13/15s依次开始爬升。进出场高度按uav1至6依次45/40.5/50/55/60/65m，返场使用本机同一高度。草区uav5直接衔接60m作业层，uav6由65m降至60m；其余仍40.5m作业。进出场处于25点周界内，树林可过境不搜索；运行时继续保留路径预约，顺序不能代替定位误差、制动和连续碰撞风险验证。

用户补充的四点 `113.70756630,33.86440447`、`113.70792269,33.86350300`、`113.70786645,33.86243604`、`113.70742227,33.86245337` 围成的区域已作为科三区域从搜索几何中扣除。规划器对该多边形增加2m保守缓冲，以避免与树林边界之间留下窄小的可扫描碎片；该区域仍在25点周界内，因此只禁止扫描，不禁止过境。草地区进出场从11—12点连线向北偏移15m形成两条门位，uav5使用西侧门位，uav6使用东侧门位，减少两架草区飞机在往返阶段的水平重合。

## 启动和取点

在WSL运行：

```bash
cd /home/zyc/zhixin_2026_ws
python3 scripts/prepare_assets.py
python3 scripts/sim_server.py --port 8765
```

已有服务先用Ctrl+C退出，重新启动后Windows浏览器打开`http://localhost:8765`并Ctrl+F5刷新。启动按钮运行网页运动学仿真，不等于启动六机物理闭环。

左键单击地图显示WGS84经纬度；拖动平移，滚轮缩放；右键复制`经度,纬度`（小数度），需要浏览器允许剪贴板访问。后端用任务统一ENU原点反算，不把卫星瓦片偏移坐标当成WGS84。卫星截图配准误差仍影响人工选点，现场需RTK复核。

验证入口：`validate_regional_scan.py`、`validate_work_only_scan_speed.py`、`validate_owned_coverage.py`、`validate_scan_protocol.py`、`validate_scan_timing.py`、`validate_simulation.py`。均为模拟配置与逻辑验证，完整科二抛投、真实云台、六机SITL和实机飞行不在本轮验收范围内。
