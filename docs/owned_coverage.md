# 分区与扫描去重优化（2026-10-06）

## 当前策略

`config/coverage_planning.json` 默认使用 `owned_scan_cells`。三区仍各两机，逐区比较东西/南北两种直线切分，以及35%至65%的七个候选位置。以预计最长扫描加站间移动时间为主要目标，兼顾站位数量、靠边惩罚和覆盖可达性。最终默认三个区均采用东西坐标切分的直线；保留20m水平作业隔离带。它是有限候选搜索，不是全局最优证明。

原来每站整块80m或120m矩形都完整扫描，邻站重叠部分也重复执行。现在将搜索地块裁剪成独立归属的目标单元，合并能由同一站覆盖的单元，删除能由其他站补齐的冗余站。飞机中心在合法导航区内向内部偏移，偏好28m边界间距，但不能承诺复杂薄片附近全部达到28m。

每站只给自己的目标单元生成蛇形扫描条带，不再固定25个视场位置。条带根据瞬时有效视场和行间重叠生成，空白区及不连通条带之间快速摆位，仿真不计摆位时间。每条真实扫描线地面速度4m/s，无观察驻留；命令携带起点与终点以及 `rapid_repoint_target_enu_m`。真实云台适配器仍需实现连续插值和快速摆位。

目标地块归属不重叠，不等于相机画面绝不重叠：房区25%、出发区10%、草区5%是行间最小重叠，画面边缘也会越过目标多边形。为保证全场几何覆盖，房区薄片可能由邻近区域飞机从其合法站位侧视补齐；飞机不跨作业边界，动态目标离开本机搜索区仍放弃。界线不是建筑遮挡模型，也不能证明目标识别完整。

重复面积指标是各站实际扫视覆盖并集的面积之和，减去全场并集，再除以搜索面积；不计同一站内部的行间重叠，也不是“重复识别概率”。不能用1.84%声称全场总画面重叠只有1.84%。路线边缘指标统计整条接触边缘带的航段长度，不是精确裁剪后的带内长度。

站位数没有显著减少，增加1个是为了内部站位与独立目标单元覆盖。减少的是无效重复扫描和云台指令密度，不通过删掉边缘目标强行减少飞机站位。

数量不同是因为各站目标单元面积不同，不再每站都执行同样的完整矩形扫描。站间路线按合法连通片分组，并在各片内做路径长度改进，减少反复跨片转场。

旧动画返场是串行安排并等待后续跨片转场结束，和已有原生分层预约返场不一致。现在名义演示按各机实际搜索结束时间生成返场候选，连续轨迹分离检查通过才放行；有冲突延迟重试。真正飞控执行器仍依据实时到达事件和12m路径预约，不使用名义动画时钟发飞行许可。新版指定进场高度及前排优先顺序下的22.60min还包含返场计时修正，不能全部归因于航点优化。

## 使用与验证

```bash
cd /home/zyc/zhixin_2026_ws
python3 scripts/prepare_assets.py
python3 scripts/validate_owned_coverage.py
python3 scripts/sim_server.py --port 8765
```

Windows打开 `http://localhost:8765`，已有服务须先Ctrl+C再重启并强制刷新。勾选扫描覆盖后，淡色多边形表示各站实际负责地块，而不是反复叠加完整矩形。实线仍为飞机站间移动，虚线为进出场/跨片转场。网页同时显示逐机站数、扫描段数及耗时。

报告为 `validation/owned_coverage_report.json`；历史基线为 `validation/pre_optimized_plan.json`。分区、站位或扫描归属改动后旧断点版本失效，应重新规划，不复用旧完成证据。

名义22.60min低于科一25min和科二搜索前段30min，但余量有限。快速摆位、扫描转角动态、真实视频帧率、机头调整、SDK与通信延迟、建筑遮挡、动态目标事件和实际路径预约等待均未充分标定；短扫描段的六帧证据也尚未在真实流中验证。科二抛投全流程未确认。结果不是比赛完成或六机SITL/实机闭环验收。
