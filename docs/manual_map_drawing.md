# 网页手绘区域与航点

已确认并需长期保留的区域修改存放在 `config/area_adjustments.json`。它们是正式规划输入，不是临时绘图痕迹；清空网页手绘草稿不会删除这些修改。启动后，正式分区/覆盖层会显示修改后的区域，独立的手绘编辑层为空。

在 WSL 中启动规划展示：

```bash
cd /home/zyc/zhixin_2026_ws
python3 scripts/sim_server.py --host 0.0.0.0 --port 8766
```

Windows 浏览器访问 `http://localhost:8766`。如果服务原来已经运行，需要先 Ctrl+C 停止旧服务，再运行上述命令，并刷新网页。

## 绘制与修改

1. 左栏“手动绘制 / 优化意见”中选择飞机（可留为未指定），填写名称和优化备注。
2. 点击“画搜索区”“画禁搜区”或“画航点”，在卫星地图上用左键逐点添加。区域至少三个点；航点按点击顺序编号。区域边界不是飞机必须绕行的航线。
3. 点击“完成绘制”（或 Enter）。区域自动闭合，航点序列不会闭合。右键或 Backspace 撤销末点，Esc 取消当前绘制。拖动空白处平移，滚轮缩放。
4. 在“已绘制对象”中选中对象，可拖动地图顶点；修改名称、飞机和备注后点“更新名称 / 归属 / 备注”。也可删除选中对象。
5. 点击“保存到工作空间”，网页显示保存路径。区域自交、面积过小、坐标或原点不匹配会拒绝保存；超周界、覆盖禁搜区会显示警告，保留原始意图供后续优化。

## 保存给后续优化

- 服务端保存位置：`/home/zyc/zhixin_2026_ws/missions/manual_drafts/latest.json`，同时保留带时间戳的历史 JSON。
- 点击“导出JSON”下载完整草稿，包含原点、科目、飞机编号、名称、备注、ENU 点和 WGS84 经纬度。WGS84 顺序是 **经度、纬度**。
- 本机后续可直接说“读取最新手绘草稿优化”。如果在另一台服务器运行，请上传导出的 JSON 文件；不需要逐个报坐标。
- “读取上次保存”恢复服务器文件；“导入JSON”恢复同一地图原点的文件。浏览器会暂存已完成的对象以防刷新丢失，但浏览器暂存不能替代服务端保存。正在绘制且未点完成的对象不暂存。
- 现阶段手绘是优化输入，不会直接执行，也不会自动改变覆盖率、隔离距离、原有分区或航线。后续需要基于草稿重算覆盖、分区、进出场、安全检查和耗时。

## 地面站式航点编辑

左栏“地面站航线编辑”会读取当前规划生成的六条航线。每个飞机的进场、转场、重定位、出场和返场航点会显示为编号航点，扫描站位仍单独由扫描规划器管理。

- 在地图上点击航点可选中，拖动可修改东、北坐标和位置；高度可在“当前点 ENU / m”中精确输入。
- 使用“前插”“后插”“删除”“上移”“下移”修改当前飞机航点顺序；顺序就是该飞机的执行顺序。
- “恢复原规划”只恢复当前规划快照；“保存航点草稿”写入 `missions/manual_drafts/mission_waypoints.json`。
- 航点草稿保存后仍需重新规划。系统会在重新规划时重新计算时间、周界、作业区间距和回场检查，不能把手动编辑结果直接当作实机安全证明。
- “应用手绘并重新规划”会读取 `latest.json` 中的搜索区和禁搜区，生成新的搜索分区和扫描航线；它不会自动把未保存的航点编辑直接写入飞控。

接口：`GET /api/manual-draft` 读取最新草稿；`POST /api/manual-draft` 保存（需要 `map_origin_id` 和 `features`）。支持类型 `search_area`、`exclude_area`、`waypoints`；每条包含 `vehicle_id`、`label`、`notes`、`points_enu_m`。所有经纬度由服务端使用当前任务原点计算，避免混用坐标系。
