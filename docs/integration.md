# 实机迁移边界与后续接口

## 已确认原则

默认原生执行器现采用分层空间预约进出场，仅跨区转场保留独占通道；完整说明与兼容的旧独占策略见 `reserved_returns.md` 与 `layered_entry.md`。以下“通道令牌”不是允许绕过新航段预约，且中央进程实现不等于已实现 LoRa 分布式协调。

六机同时离地，随后高到低入场放行；home来自现场每架机位置，机号固定。所有机使用同一地理ENU原点，不能拼接各自飞控的LOCAL_NED原点。GPS2是接口标号，不能据此认定GPS2_TYPE或SERIALx；实际串口映射与单UM982双天线航向方案需核对。

通信/云台异常：保留飞机扫描站位、云台观察点、任务epoch及命令ID，优先恢复原任务；能继续就继续。不因短暂心跳异常立即RTL。定位失效、严重电量不足等真正危及飞行时另按风险等级处理，不能无限重试。返航必须使用协调过的航线和时空预约；避免多机独立随意返航。动态目标离开本机作业区即放弃，不交接、不越区跟随。

不通过LoRa传图像、视频或ROS全集。机载视觉就地处理；网内只传必要位置/任务拥有权/目标摘要/预约/恢复信息。当前仿真没有LoRa带宽或丢包模型。需要确认自组网路由而非沿用旧文档星型假设。

## 三个待实现适配层

| 层 | 输入/输出 | 当前状态 |
|---|---|---|
| 飞行控制 | arm、GUIDED、takeoff、目的点、当前位置/模式/到点反馈 | 原生六机SITL已接入；真实硬件链路和全球坐标适配尚未验收 |
| 云台视觉 | 逐点观察命令、接单/执行/失败状态、有效观察证据、原点重试 | 当前HTTP逐点版本/尝试/会话及证据门控已实现；ROS2 Action/SIYI SDK/YOLO未接，START_TRACK未接真实跟随 |
| 多机协调 | 任务版本、home、通道令牌、最小必要位置和恢复状态 | 中央SITL通道令牌已实现；网络仲裁与失联行为未接 |

建议的ROS2+MAVROS实机控制链路尚待用户最终确认。SITL执行器使用pymavlink、六个独立进程、sysid与TCP端口；发布下一GUIDED航点并根据LOCAL_POSITION_NED到达/稳定反馈推进各机游标，空间预约控制进出场，独占令牌保留用于跨区转场。已按各机GPS_GLOBAL_ORIGIN做WGS84/ECEF/ENU转换，起飞前读取实际位置自动规划；不是简单home平移。实机仍须核对高程基准/大地水准面差、AGL、RTK与EKF原点变化行为。反馈到点不代表云台观察完成，扫描仍必须由任务适配器确认；详细数学和起点流程见 `coordinates.md`。

当前航点状态机由实际事件推进，中央服务持有通道令牌；尚非分布式ROS2/LoRa网络仲裁。暂停/恢复不清空游标，落地等待实际解除锁定。4.7.1单独构建并读回版本，验证报告必须区分原生SITL物理、Gazebo显示与硬件三个层级。

## 人工完成接口（仅演示，不是实机契约）

```json
{
  "action": "result",
  "mission_epoch": "从/api/state读取",
  "vehicle_id": "uav_1",
  "command_id": "uav_1:0:0",
  "status": "FINISHED"
}
```

POST `/api/control`，完成值仅接受 FINISHED / SUCCESS_FOUND / SUCCESS_NOT_FOUND。过期epoch拒收，重复command_id幂等，非当前等待点拒收。此接口只证明任务门控，不证明图像成功解码、有效YOLO帧数、视角、倍率或目标位置正确。实机需按视觉规格补 `calibration_id`、`surface_model_id`、姿态/倍率反馈、时间戳和真实有效观察证据。

实机适配开发应以 `gimbal_protocol.md` 中逐点观察契约为基线，而不是上面的人工完成接口：按机号领取 `/api/gimbal/command`；带当前命令的身份/版本、`attempt_id` 和 `executor_session` 先向 `/api/gimbal/status` 报告 ACCEPTED，再报告 RUNNING；完成后向 `/api/gimbal/result` 提交当前观察窗口的有效证据。失败保留原点，恢复后经 `/api/gimbal/retry` 获取新尝试，不沿用旧尝试证据。当前这些接口仍未证明真实视觉或云台成功。

## Gazebo显示层验证

`validation/gazebo_gimbals_report.json` 验证六个机体和六个独立云台显示模型的位置回放，以及正下方姿态的光轴方向；另有六组纯数学方位/俯仰投影检查。验证读取六机未解锁的原生反馈，不请求暂停、起飞或修改任务，前后任务epoch与游标保持不变。

在两个终端分别运行 `bash scripts/run_gazebo.sh -s` 和 `python3 scripts/gazebo_replay.py --url http://127.0.0.1:8766`，六机静止未解锁时用 `python3 scripts/verify_gazebo_gimbals.py` 复验。验证不自动暂停正在飞行的任务。Gazebo采用set_pose显示，不模拟云台关节动力学、相机图像、真实遮挡或碰撞；机体姿态显示也未接实时滚转/俯仰。它不能代替真实Gazebo相机与SIYI链路验收。

## 附件与新要求冲突

- 旧规格45m相对起飞点，当前用户40m侦察、规则采用AGL；需要地形/测高来源，不用相对home偷换AGL。
- 旧规格固定任务表不自动改点，当前用户希望自动生成；建议起飞前生成并校验后固化任务版本，飞行时不静默改点。
- 旧策略心跳0.5~1s报警不能直接变成即时RTL；用户要求恢复优先。实际超时和恢复次数仍需链路试验确定。
- ZR10标称30倍含混合变焦，不能当30倍光学；实测各倍率内参/FOV、云台角范围和视线坐标。当前云台方位是ENU方位，不是可直接发送的SIYI yaw。
- 静态确认10s可作候选确认；移动目标满评分涉及多次轨迹上报，不能只跟10s就结束。

## 必须确认而不能伪造的项目

1. 科三区树林是否允许40~120m高层过境；若全高度禁止，现有起降点到东侧任务区不连通。
2. 当前按全高度禁飞检查；默认路线有5段穿越，禁止启动。10m端部通道候选尚待用户确认，详情见 `isolation_airspace.md`；树林许可不能授权穿越隔离带。
3. 视觉组提供实际扫描矩形、倍率和有效扫描耗时；当前模拟参数下科一超时。
4. 科二任务卡、抛投载荷/次数、目标与补给过程。现阶段不臆造。
5. 实机控制链路、可接受飞行误差、LoRa位置更新率、断链后的各机共同安全策略。

## 后续物理闭环验收顺序

先单机SITL：真实解锁、起飞、位置变化、到点悬停、云台完成门控、返场；再独立sysid/端口六机并发；注入延迟/丢包并读回实际连续轨迹；最后接真实ROS视觉与分段舵机。任何一级没有证据，不把前一级显示成功当作后一级飞控验证成功。
