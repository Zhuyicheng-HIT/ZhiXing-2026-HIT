## 规划、状态与当前结果

`scripts/fleet_core.py` 统一生成区域、可飞区域、扫描站位与完整时间轴，网页和Gazebo读取同一后端。工作区内不可直达的点使用可视图最短通路；不连通子区只能在已明确授权的高层过境假设下重新定位。扫描覆盖用矩形并集核验，剩余缺口会在地图显示红色；**几何100%不代表遮挡、图像识别或有效观察100%**。

任务状态包括：

```text
TAKEOFF -> WAIT_RELEASE -> CLIMB -> INGRESS -> DESCEND_TO_WORK
-> NAVIGATE -> STABILIZE -> SCAN
-> CONFIRM_STATIC / TRACK_MOVING -> 下一观察点
-> WAIT_RETURN_SLOT -> RETURN_CLIMB -> EGRESS -> RETURN_DESCEND -> LAND -> COMPLETE
```

每个站位生成9个模拟云台地面观察点，2s/点。第一个站位有10s静态确认，第二个站位有120s移动目标**云台跟踪计时占位**。尚未生成真正动态目标，也没有机体跟随目标、目标移交和实际定位/赛事POST上报；这不是视觉策略实现完成。

当前默认80m配置：112个飞机扫描站位、1008个云台观察点，理想平面矩形名义覆盖100%；运动学串行返场名义27.20分钟，不是原生耗时预测。当前原生双科目搜索约29.34分钟，**科一25分钟仍未通过；科二30分钟仅搜索前段暂满足，不含投放**。80m与2s观察均未实测标定，不代表实际识别性能。必须用实测扫视范围与有效观察耗时优化航线/调度，不用加速播放冒充提速。

`sim_server.py` 是事件门控的运动学演练；`sitl_server.py` 加 `waypoint_executor.py` 是实际到点事件驱动的飞控执行器。飞控目标为下一航点，暂停/故障锁存当前位置；没有位置/速度轨迹前馈，也不按计划时间宣称到达。两者的云台/视觉仍为合成或HTTP完成事件，不是完整机载ROS2状态机。实机适配工作与状态/异常表见 `docs/integration.md`。

SITL起飞前自定义摆放与科目：编辑 `config/sitl_mission.json`，启动时增加 `--mission-config config/sitl_mission.json`。home控制初始摆放；点击启动时从六机实际LOCAL_NED和EKF原点读取统一ENU起点，自动生成并冻结航线，检查起降框和机间距。`subject: 2` 改用科二时限/任务标记，但仍不生成尚未确认的投放任务。SITL读取不代表已接入实机RTK。扫描矩形参数不得当作经过标定的相机覆盖。
